# 中英混合本地转写引擎选型

核查日期：2026-10-19。此文件保留最初候选方案判断。

> 后续执行变更：用户要求部署 OpenVINO，最终明确只用 Qwen3-ASR-1.7B + OpenVINO，停止0.6B路线。以 [当前部署与验证说明](OpenVINO本地中英转写部署.md) 为准，下文的 sherpa-onnx 是此前方案，并非当前程序使用的引擎。

## 建议

本程序下一步优先测试 **Fun-ASR-Nano-2512 + sherpa-onnx INT8/CPU**，作为需要用户主动选择的中英混合本地引擎。现有云端方案仍保持默认。模型只有通过本机课堂样本测试后，才适合宣布为正式替代方案。

本机只读硬件查询结果：Intel Core Ultra X7 358H、Intel Arc B390 核显、约32GB内存。

## 为什么优先这个组合

- Fun-ASR-Nano 是约0.8B的模型，官方模型卡支持中文、英文等语言，并介绍混合语言识别。
- sherpa-onnx 已提供 FunASRNano 的离线模型配置、INT8权重、Windows支持和 C/Rust 接入路线。离线一词指分段识别，不代表必须等整节课结束。
- sherpa-onnx 文档所列三个INT8网络文件合计约949MB，加上分词器等文件约1GB；实际运行内存需另测。
- OpenMOSS 公布的同一中英混说评测列中，Fun-ASR-Nano 为11.23，SenseVoice-Small 为13.90，越低越好。该表不能证明它胜过未列出的Qwen3-ASR或FireRedASR2，也不是本机课堂测试。
- 相比直接引入完整Python/CUDA环境，独立的本地识别辅助进程更适合目前Windows桌面安装包；这是工程判断。

## 其他候选的定位

| 候选 | 在本程序中的用途 | 取舍 |
| --- | --- | --- |
| Fun-ASR-Nano-2512 / sherpa-onnx INT8 | 优先测试的中英混合本地应急识别 | 按语音片段输出，需实测延迟和专业词 |
| Qwen3-ASR-0.6B / 1.7B + OpenVINO | 用Arc B390做质量、速度对照 | 官方已有OpenVINO支持，仍需独立转换、部署和验证 |
| 双语Zipformer / sherpa-onnx | 强调边说边出字的本地模式 | 有中英双语流式模型；不能假定准确率优于较新的模型 |
| SenseVoiceSmall INT8 / sherpa-onnx | 占用和速度对照 | 值得作为轻量候选，不凭参数或单一测试预判课堂效果 |
| FireRedASR2-AED | 后续录音精修及质量对照 | 官方支持中英混说，但当前没有本机Intel部署与持续识别实测 |

已下载的 Parakeet-TDT-0.6B-v3 不支持中文，不能作为用户中文/中英混合课的主本地引擎。Qwen3.5-4B 是本地摘要模型，与语音识别引擎分开选择和验证。

## 接入时必须同时处理的部分

1. 替换本地ASR适配器，保持现有麦克风采集、原始录音存储、转写入库和摘要界面。
2. 当前 local.rs 使用固定8秒音频块。建议改为VAD检测停顿并设置最大段长，避免硬切词、长时间不出字；具体时长由样本测试确定。
3. 将识别放入独立进程，隔离运行库依赖和崩溃，支持启动检查、超时、队列上限及错误提示。模型保持加载，不能每段重新启动大模型。
4. ASR积压时显式提示；原始音频独立保存。点击补听时说明最近片段是否仍在识别，不能把未识别完冒充没有内容。
5. 课程术语使用所选引擎实际支持的上下文/热词接口；不假设云端的提示词字段可原样通用于所有本地引擎。
6. 片段时间应以真实音频采集时间计算；没有对齐器验证的逐词时间戳不可当作精确词级定位。
7. 云端与本地切换必须由用户选择并保存；检测或下载成功不切换，断网/报错也不暗中切换。录制中不直接更换引擎。
8. 首版只运行一个ASR模型，先测它与本地Qwen摘要同时工作时是否有转写积压，再考虑双引擎策略。

## 验收建议

使用同一份5–10分钟的课堂样本比较Nano与至少一个对照，覆盖纯中文、纯英文、句内混说、专业词/数字/任务、停顿和环境噪声。

检查专业词及任务关键词是否正确、从说话到显示的延迟、长段重复/漏字、CPU/内存及发热。平均处理时间必须小于音频时长，并继续做90分钟录制与摘要并行的积压测试。32GB内存和核显型号本身不能替代这些验证。
