# 课程修复与检查点恢复

左侧课程“…”菜单新增“修复课程”。适用于中断后没有合并音频，或需要核验已保存录音的情况。录制、暂停、收尾中的目标课程不能修复；当前补听生成中也需等待完成。

## 修复会做什么

1. 校验课程文件夹确实属于当前课程，拒绝越界路径或文件链接。
2. 在项目 `data-backups/` 保存修复前的一致性SQLite数据库备份。
3. 将元数据、转写导出和时间映射的原文件复制到课程内 `.repairs/本次编号/`。
4. 对现有合并音频执行完整解码核验；若没有有效合并音频，则按数字编号核验 `.checkpoints/audio_chunk_*.mp4`，合并连续可恢复的前段，并核验新音频。
5. 生成新的 `audio-recovered-编号.mp4`，保留全部原检查点和原音频。已有有效修复音频可复用，重复修复不重复导入同一时间的已确认转写。
6. 对照本地转写导出，把数据库缺少的已确认内容补回；同一时段以数据库已确认版本为先。未确认转写保持未确认，不凭空补写内容。
7. 比较可恢复音频与时间映射，生成修复报告。只有音频核验完成后才提交数据库状态。

## 状态含义

- **已修复**：恢复音频通过核验，现有记录未显示明显缺口；这不代表重新辨认了课堂内容。
- **部分恢复**：检查点已修复，可播放已落盘部分，但尾部或中间有缺失，或缺少可靠的时长依据。具体原因见提示和报告。
- **仍为中断待核实**：没有可核验的音频、路径有问题，或修复提交失败；原文件保留，不能仅修改标签冒充恢复成功。

如果中间检查点缺号或损坏，只合并其前面连续的音频，后续检查点仍保留。这样不会把后续内容提前拼接，造成原文回放时间错位。不能靠修复凭空找回从未写入磁盘的尾部声音。

## 文件在哪里

- 原检查点：课程目录的 `.checkpoints/`，修复不删除。
- 新音频：课程目录的 `audio-recovered-编号.mp4`。
- 当前选用音频和已核验时长：`repair-state.json`。
- 本次修复详情：`.repairs/编号/report.json`。
- 原元数据、转写、映射及上次修复指针备份：同一 `.repairs/编号/` 下的 `original-*`。
- 恢复后的结构化转写副本：`.repairs/编号/transcripts-recovered.json`。
- 数据库提交记录及备份位置：`.repairs/编号/database-committed.json`。

原 `transcripts.json`、原始云端事件和所有补听卡片均保留。若转写比实际保存的声音更长，文字仍可阅读，但尝试跳转到缺失的录音尾部会明确提示无法回放。

## 验证方式

`tests/repair/` 直接测试生产修复模块：完整解码、损坏首块、检查点缺号、数字排序、保留原文件、重复修复去重以及路径越界拒绝。`tests/native-repair.cjs` 在隔离课程中验证真实Windows菜单、数据库备份、补回转写、播放路径和缺失尾部保护。测试不联网，不调用语音/摘要API。

用户指定课程的实际修复结果以本机修复报告为准，不能把模拟测试当作整节课完整恢复的证明。
