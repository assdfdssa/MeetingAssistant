## 1. 决策与基线

首版代码入口与本清单后续规划分开标注：界面为 `meetily/frontend/src/components/classcatch/Classroom.tsx`；原生服务为 `src-tauri/src/classcatch/service.rs`，云端识别为 `cloud.rs`，窗口与引用校验为 `core.rs`，音频重采样与暂停映射为 `dsp.rs`。下文尚未勾选或以阶段描述的条目保留为设计和验收清单，不能视为全部已实现。已验证和未验证的内容以[验证记录](./开发进度与验证.md)为准。

用户已确认Meetily Community Edition是唯一主底座。技术栈固定为Tauri、Rust、Next.js/React、TypeScript，优先Windows 10/11。API调用使用用户自备密钥，音频和历史保存在本机。

以[Meetily v0.4.1](https://github.com/Zackriya-Solutions/meetily/releases/tag/v0.4.1)作为建议复现基线，开工时解析并记录其commit SHA。该版本有已核实的Windows安装资产，但本项目尚未实际构建或安装。研究阶段读取过main源码，部分改进可能不在该tag；必须逐项核对后决定移植，不能混用不同版本文档和代码。

保留上游LICENSE和版权声明；建立fork自己的应用名称、应用标识、数据目录与更新渠道。PRO代码、商业素材和服务不算社区版可复用内容。

## 2. 复用与新增映射

下表路径来自研究中看到的仓库结构；开工后在固定基线核实。新增目录和命令名是设计，不代表上游已实现。

| 领域 | 上游入口/能力 | 本项目动作 |
|---|---|---|
| 界面 | frontend/src | 增加课堂页、时间选择、补听/任务/解释模式、浮动卡片 |
| 桌面壳 | frontend/src-tauri | 沿用窗口、托盘、构建与生命周期 |
| 录音命令 | frontend/src-tauri/src/audio/recording_commands.rs | 保留采集所有权；按ASR provider调整启动校验 |
| 音频管理与保存 | audio目录下录音/转写/保存模块 | 核查音频格式、分片、样本偏移、断线恢复、转写持久化 |
| 转写事件 | transcript-update及相关类型 | 统一云端partial/final/revision与本地历史，避免双份字幕 |
| 快捷操作 | 现有快捷键、托盘和浮窗入口 | 新增独立补听快捷键，不复用停止录音快捷键 |
| 摘要提供商 | 已有摘要配置与调用能力 | 能复用则扩展；新增独立按需补听作业，不依赖停止录音 |
| 数据存储 | 现有数据库和录音文件 | 建立meeting_id与课程session映射，新增版本/证据表，迁移可恢复 |
| 新业务 | 建议src/classcatch | 云端适配、时间窗口、证据快照、摘要验证、任务和恢复模块 |
| 课件 | v0.2 | 优先Rust组件，解析一次并缓存页码与术语；不默认增加Python后台 |

不先整体改名目录或重写上游模块。优先小改动、薄适配和独立业务模块，降低上游修复移植成本。

## 3. 云端识别改造是首要工程任务

1. 新增ASR提供商枚举与设置，至少区分云端与本地模式；不能把文本摘要服务配置当作ASR配置。
2. 云端模式启动时检查密钥、地域、音频格式和连通性，跳过只属于本地ONNX/模型下载的前置条件。
3. 从现有Rust采集路径取得音频，一路持续保存，一路进入有界ASR发送队列；采集回调不做网络请求。
4. 云端适配器管理连接、推流、断句、确认事件、偏移和重连；云端转写进入统一存储与历史。
5. 不同时启动不必要的本地Whisper/Parakeet识别，以免首次下载、CPU占用或重复文本。
6. 连接失败保留录音，清楚显示待转写范围。额度错误与麦克风故障分别提示。
7. 先支持一个经过同录音对比的默认识别服务；保留接口扩展，不一次实现多家。

## 4. 快捷键到补听卡片的调用链

```text
Rust全局快捷键处理器
  → 记录按键锚点T，读取上次模式与范围
  → 通过与按钮相同的应用服务建立catchup作业
  → 查询所选范围已确认转写、水位和版本
  → 构建不可变证据快照
  → 异步调用文本模型
  → 校验结构/引用，写入历史
  → Tauri事件/Channel更新卡片
```

音频采集、ASR和写盘独立继续运行。全局快捷键只在Pressed触发一次，去除按键重复事件；浮窗未加载时后台仍能记下锚点和作业，界面加载后查询当前结果，不能只靠易错过的一次事件。

补听输入是完整选定窗口，不是上次自动摘要的增量，也不是会后摘要。卡片固定到T，后续字幕补齐只显示更新入口，避免学生阅读过程中内容跳动。

## 5. 类型与事件约定

Rust定义请求/结果结构体并进行serde序列化，前端有对应TypeScript类型，避免同一字段在两侧含义不同。字段至少包含session/meeting关联、锚点、范围、模式、job_id、来源版本、覆盖水位、任务原话和证据引用。

建议新增request_catchup、get_catchup_job、cancel_catchup_job和补听状态事件；具体上游录音命令复用现名或加薄封装，详细列表见[主开发文档第13节](./课堂补听助手-开发文档.md#13-tauri命令与事件规格草案)。命令是内部IPC，不是对外HTTP API。

快捷键不依赖前端组件始终挂载；录音状态以Rust应用状态为准，不以React页面是否可见为准。异步生成不能长期持有录音或数据库的全局锁。

## 6. 数据与安装迁移

- 复用上游数据访问层并增加版本化迁移；先核对上游实际schema，不把设计中的app.sqlite直接覆盖到其数据库。
- class_session保存对应meeting_id，录音文件清单保留上游引用与时间偏移；新任务、摘要证据表不破坏原会议历史。
- 调整应用标识和数据目录后，显式提供旧数据导入；不直接读写官方Meetily目录，避免两程序并发访问同一数据库。
- Rust凭据存储由系统保护，前端不读回完整密钥。旧密钥迁移需要用户主动确认或重新输入，不自动复制不明配置。
- 构建Windows EXE/MSI，处理WebView2与上游所需原生依赖；云端模式不附带必下载的大模型。
- 使用fork自己的更新源或关闭自动更新；不能让官方更新覆盖自定义功能。更新保留数据，数据库升级先备份。
- 原始音频、实时事件和最终转写都要保存，验证“已保存”的实际文件与数据库内容，而不只看UI提示。

## 7. 开发任务顺序

| 阶段 | 产物 | 必须验证 |
|---|---|---|
| M0 基线 | 上游tag/SHA、锁文件、干净Windows构建记录 | 安装运行、设备选择、保存回放、许可清单 |
| M1 云端录课 | 一家云端ASR、统一事件和本地存储 | 无本地模型也能启动；50分钟录音与转写对齐 |
| M2 按需补听 | Rust命令、三模式、可选时间、快捷键、卡片 | 摘要期间采集不断；按键锚点与缺口提示正确 |
| M3 可交付v0.1 | 安装包、图形配置、历史、诊断和恢复 | 干净Windows；两节50分钟加课间，至少120分钟测试 |
| M4 课件v0.2 | PDF/PPTX、术语、页码检索与解释 | 有无课件对照，任务不从课件凭空生成 |
| M5 网课与优化 | 系统音频、可选翻译、补转写 | 混音不重复、字幕不重影、费用可追溯 |

基线或功能验证失败时，记录故障与修复，不回退成“三底座并行尝试”。主底座变更需另行说明实际阻碍与范围。

## 8. 入门学习路径

先阅读一个现有React按钮如何invoke Rust命令，再看Rust怎样发回事件，最后接触录音管理器。建议依次掌握：TypeScript类型、React状态、Rust结构体与Result、async/await、Tauri命令/事件、音频时间轴和持久化。

Python仍可用于独立分析实验与测评，但不成为软件必需的第二套后台。新功能入口是Meetily的Rust/Tauri主线，不能因仓库残留Python目录就把课堂核心逻辑写到其中。

## 2026-10-19 提问、分层补听及紧凑操作区

当前三个主入口为：补听重点（原提示词及输出保留）、提问（自写问题或默认总结，约500字一段回答）、分层补听（主线加可展开重点）。新模式支持最近范围及指定课堂起止时间；操作区可收起，生成入口保持可见。历史菜单显示当前课程全部已保存卡片，并支持搜索，不再截取四条。

旧 tasks/explain 卡片保持可读，旧设置模式映射到 ask/layered。课堂事实引用仍进行后端校验；AI解释、举例和关系梳理与课堂复述明确分开。详见 docs/提问与分层补听使用说明.md，实际提示词见 docs/API提示词清单.md。

当前验证：核心逻辑9项通过；四种尺寸的提问/分层/15条历史交互验证通过。界面使用模拟模型响应，不代表真实云端生成质量；Windows实测及最终打包结果以本节后续交付记录为准。
